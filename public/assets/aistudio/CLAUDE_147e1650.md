# Urban Air Quality Assistant (PromptWars Challenge 06)

## Goal
A functional GenAI web app with clean UI/UX that, given a user's city/AQI and
lifestyle profile, returns:
1. **Tailored low-emission routines** (outdoor timing, commute, swaps)
2. **Indoor air quality hacks** (cheap, practical, home-specific)
3. **Clear impact explanations** (every suggestion says WHY it helps)

This is a hackathon submission with 3 attempts. **Ship v1 fast. Keep it simple.**
Do not add features beyond this spec (no auth, no database, no maps).

## Stack
- Next.js (App Router) + TypeScript (strict) + Tailwind
- zod for input and LLM-output validation
- Open-Meteo Air Quality API (free, no key) for live AQI / PM2.5
- LLM called only through `src/lib/llm.ts` -> `generate(system, user): Promise<string>`
  (provider-swappable; key in `.env.local` as `LLM_API_KEY`)
- Deploy: Vercel

## Data flow
POST /api/advise
1. Validate input (zod)
2. Get AQI: Open-Meteo by city (geocode first) OR use the manual AQI if given
3. Build prompt via `prompts.ts` (AQI facts injected, never invented by the model)
4. Call LLM -> JSON only
5. Validate with zod; on failure retry ONCE with the validation error appended
6. Return the plan; UI renders cards

## Input schema
- `city?: string` and/or `manualAqi?: number` (at least one required)
- `commute: "walk" | "bike" | "bus" | "car" | "two-wheeler" | "work-from-home"`
- `home`: `{ ventilation: "windows" | "ac" | "both" | "poor", cookingFuel: "lpg" | "induction" | "biomass" | "other", nearBusyRoad: boolean }`
- `sensitivities: ("asthma" | "children" | "elderly" | "pregnancy" | "none")[]`
- `outdoorHours?: number` (per day)

## Output schema (enforce with zod)
```json
{
  "summary": "string",
  "aqiBand": "Good|Moderate|Unhealthy-Sensitive|Unhealthy|Very Unhealthy|Hazardous",
  "outdoorRoutine": [{ "action": "", "timing": "", "why": "", "impact": "low|medium|high" }],
  "indoorHacks": [{ "hack": "", "cost": "free|low|medium", "why": "" }],
  "lowEmissionSwaps": [{ "swap": "", "estimatedBenefit": "" }],
  "healthNote": "string",
  "disclaimer": "string"
}
```
Rules: 3-5 items in `outdoorRoutine`, 4-6 in `indoorHacks`, 2-3 in
`lowEmissionSwaps`. Every item must have a non-empty `why`/`estimatedBenefit`.

## AQI bands (US AQI scale)
0-50 Good | 51-100 Moderate | 101-150 Unhealthy-Sensitive | 151-200 Unhealthy |
201-300 Very Unhealthy | 301+ Hazardous

## Prompt rules (implemented in prompts.ts)
- Advice must change meaningfully per band and per sensitivity group.
- Tie every recommendation to the user's profile and the current AQI.
- Use only AQI/PM2.5 numbers given in the prompt. Never invent figures.
- Estimated benefits must be qualitative or hedged ("can noticeably reduce"),
  never fake precise percentages.
- India-relevant context where applicable (cooking fuel, two-wheeler masks,
  stubble-burning / winter inversion season, festival firecrackers).
- Prefer free or cheap actions first.
- No medical diagnosis. Include a short disclaimer.
- Respond with JSON only: no markdown fences, no preamble.

## UI requirements
- Mobile-friendly, single page, clean spacing, color-coded AQI badge
- Loading skeleton + clear error state (API failure, invalid LLM JSON)
- "Why this helps" visible on every suggestion, not hidden behind clicks
- Sensible defaults so the demo works with one click

## Code conventions
- TypeScript strict, no `any`
- Small files, no premature abstraction, ~600 lines total target
- Never expose `LLM_API_KEY` to the client; all LLM calls happen in the route
- Commit after each build step

## Build order
1. schema.ts  2. aqi.ts  3. prompts.ts + llm.ts  4. route.ts
5. UI components + page.tsx  6. tests + README  7. deploy to Vercel

## Definition of done (v1)
- Works end-to-end on the deployed URL with a real city
- Works with manual AQI when the Open-Meteo call fails
- Output validates against the schema on all 3 sample profiles
- README explains the prompt design
